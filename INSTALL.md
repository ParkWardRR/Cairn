# Installing and building Cairn

Cairn is built from source; there are no prebuilt release artifacts. (The
v0.1.0 tool tarballs — `tripctl`, the Odin tools, `cairn-trajectory` — no longer
exist; see the "Retired" row under Decisions in [ROADMAP.md](ROADMAP.md).)

| Part | Where | Toolchain |
|------|-------|-----------|
| Server and admin tools | `server/` | Go 1.27 (`server/go.mod`); a C toolchain for `cairn-tsdb` only |
| Firmware | `firmware/cairn-v2/` | PlatformIO (`espressif32@7.1.3`, Arduino-on-ESP-IDF) |
| Emulator / conformance checker | `emulator/` | Rust (edition 2024), `cargo` |
| Web UI | `ui/` | Node.js and `npm` (Nuxt) |
| Database schema | `deploy/migrations/` | PostgreSQL with PostGIS; `001_raw.sql` … `005_vehicle.sql`, applied in order |

## Server

```bash
cd server
make build          # cairn-server cairn-admin cairn-verify cairn-ledger cairn-signfw -> ./bin
make build-tsdb     # cairn-tsdb (DuckDB via cgo, so it needs a C toolchain) -> ./bin
make test           # go test ./...
make vet
```

`make build` picks `GOAMD64=v3` on hosts that support it and falls back to `v1`
with a warning; see the header of `server/Makefile`. Other binaries under
`server/cmd/` (for example `cairn-provision`, `cairn-worker`, `cairn-push`) are
not in the Makefile's list; build one with `go build ./cmd/<name>`.

To run it on a host as a service (mutual-TLS device listener, certificates,
receipt key, systemd unit), follow [docs/deploying.md](docs/deploying.md). The
deploy script builds on the target and installs the units:

```bash
deploy/deploy-v3.sh <user@host>
```

Certificates for the device path come from `deploy/make-certs.sh`
(`init`, `device`, `ca-literal`); `deploy/certs/` is gitignored.

## Database

Apply the migrations in order to a PostgreSQL + PostGIS database, as CI does:

```bash
for f in deploy/migrations/*.sql; do
  psql -d cairn -v ON_ERROR_STOP=1 -q -f "$f"
done
```

## Firmware

```bash
cd firmware/cairn-v2
cp include/secrets.h.example include/secrets.h   # then fill in your own values
pio run -e cairn            # production capture image
pio run -e cairn-selftest   # bench self-test image; flash this first
```

`secrets.h` is gitignored. The same `-e` names work with `-t upload
--upload-port <port>`. Other environments: `cairn-ble`, `cairn-pidtest`,
`cairn-mtprobe`, `cairn-mtprobe-sniff`. The vendored FreematicsPlus drivers in
`firmware/freematics-base/lib` are picked up automatically.

Flashing, the self-test, and first-boot checks: [docs/v2-firmware-testing.md](docs/v2-firmware-testing.md)
and [docs/flashing-and-testing.md](docs/flashing-and-testing.md). Enrolling the
dongle and giving it credentials: [docs/device-provisioning.md](docs/device-provisioning.md).
The first end-to-end drive: [docs/hardware-roundtrip.md](docs/hardware-roundtrip.md).

## Emulator and conformance

The emulator has two subcommands, `conformance` and `fault-matrix`:

```bash
cd emulator
cargo test
cargo run --release -- conformance --vectors ../fixtures/format-v3
cargo run --release -- fault-matrix --work-dir target/fault-matrix --verbose
```

The format vectors are generated by the Go reference
(`cd server && go run ./cmd/mkvectors -out ../fixtures/format-v3`) and must
regenerate with no diff. The C firmware's host suites run with
`make -C firmware/cairn-v2/test/host` (and `... asan`).

## Web UI

```bash
cd ui
npm install
npm run dev         # development server
npm run build       # production build -> .output/
```

The UI reads the analytical store through server-side routes that proxy to
`cairn-tsdb` (`NUXT_TSDB_URL`, set to `http://127.0.0.1:8480` in `deploy/systemd/cairn-ui.service`). To deploy it behind Caddy:

```bash
deploy/deploy-ui.sh            # builds HEAD and installs it
```

`deploy/deploy-ui.sh` has the target host hard-coded near the top; edit `HOST`
for your own. Caddy fronts the UI only: device ingest terminates its own mutual
TLS and is deliberately not behind a proxy (see [docs/deploying.md](docs/deploying.md)).
